# UC-001 Start a game

| Field | Value |
| --- | --- |
| ID | UC-001 |
| Primary actor | Player |
| Goal | Start a reproducible game with the configured board, state and piece source. |
| Status | Approved |
| Linked requirements | FR-003, FR-008, FR-014, FR-019, NFR-001, NFR-002, C-001, C-004 |
| Entities | Variant, BoardShape, HexBoard, GameState, Tray, Piece, Level, Goal |

## Preconditions
- The player has selected a `Variant`.
- The selected variant has a valid configuration.
- A seed is available to the random source when the configuration requires random generation.

## Trigger
- The player selects a new game or a level.

## Main success scenario
1. Player selects a new game or a level.
2. System loads the selected `BoardShape`, initial `GameState`, `Tray` or level setup, and configuration.
3. System creates the generic engine with the selected rules, piece source, scoring policy and seed.
4. System presents the initial `GameState` with status active, score zero and the configured board contents.

## Alternative flows
- **A1 (at step 2) the player selects a level-based variant:** 1. System loads the selected `Level` and its `Goal`. 2. System creates the initial state from that level. 3. Use case continues at step 4.
- **A2 (at step 2) the selected variant is endless:** 1. System creates the initial state without a `Level`. 2. Use case continues at step 4.

## Exception flows
- **E1 (at step 2) the configuration is invalid:** System reports the configuration error and does not create an active `GameState`.
- **E2 (at step 3) the random source cannot provide a value:** System reports the random-source error and leaves the game unstarted.

## Postconditions
- Success: One active `GameState` exists and its initial snapshot is available to the output boundary.
- Failure: No active `GameState` is created and no progress or score is changed.

## Business rules
- BR-001-1: The generic engine receives the board, rules, piece source and scoring policy through abstractions.
- BR-001-2: A given configuration and seed produce the same initial random content.
- BR-001-3: The board contains only cells included by its `BoardShape`.
- BR-001-4: The application layer does not depend on UI, storage or random-source implementations.
